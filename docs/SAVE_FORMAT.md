Bannerlord uses **attribute-driven graph serialization**, not manual read/write.

### Auto-generated accessors — a useful signal

Types carry compiler-emitted accessors like `Ship.AutoGeneratedGetMemberValue_owner(object)` and `Ship.AutoGeneratedStaticCollectObjectsShip(object, List<object>)` (VERIFIED). These enumerate exactly the persisted members and the object-graph edges, and they are a reliable cross-check on which members are actually serialized.

## 2. The Save Is the Source of Truth

For an authoritative-server co-op mod, the **server's campaign save is the single source of record**:

- Clients never write saves of the shared world.
- Server autosaves on a schedule and on clean shutdown.
- Server restart = load that save + rehydrate registries (`NETWORK_PROTOCOL.md` §7).
- `Campaign.SupportsSaving` (VERIFIED property) is checked before any save attempt.

## 3. What We Must Persist Ourselves

Three categories, all via our own `CampaignBehaviorBase.SyncData(IDataStore)` and/or a `SaveableTypeDefiner`:

### 3.1 Player identity bindings (required for reconnect)

```
playerIdentity (platform id) → MobileParty MBGUID
                             → Hero MBGUID
                             → clan/kingdom association
```
Without this in the save, reconnect after a server restart is impossible.

### 3.2 Ship identity registry (RISK-01)

```
nextCoopShipId : ulong
per owner (MBGUID + ownerKind):
    ordered CoopShipId[]  aligned to PartyBase.Ships
per ship (fingerprint fallback):
    (ShipHull.StringId, name, hitPoints, sailHitPoints, RandomValue)
```
`Ship._versionNo` is **not** `[SaveableField]` (VERIFIED) — it resets on load and must never be persisted or used as identity.

### 3.3 Session/world metadata

Protocol version, mod version, pinned game version + `ApplicationVersionType`, War Sails build number, server config, ban list, world creation timestamp.

## 6. Design Rules

1. **Never hand-serialize engine types.** Let the engine own its graph; we persist only ids and our own data.
2. **Persist ids, not references**, in our own blobs.
3. **Version our blobs.** Every `SyncData` payload begins with a schema version so migration is possible.
4. **Fail loudly.** A missing/incompatible registry block is a hard error, not a silent default — silent defaults corrupt worlds.
5. **Save of record is server-only.** Clients may keep a local cosmetic cache, never authoritative state.
6. **Never persist `[CachedData]`.** Directly readable from metadata; enforce it in codegen.
